# Agent i18n 工作流

供 Agent 执行站点词条翻译和 i18n 接入维护任务。人工操作见[翻译指南](../.github/translation-guide.md)，命令用途、读写范围和加载原理见[开发说明](../scripts/x18n/README.md)。

## 定位任务

1. 读取 [x18n.config.ts](../x18n.config.ts)，确认资源、目标语言和检查规则。语言列表与源语言以解析后的配置为准，不另写一份语言清单。
2. 区分文章、界面词条和站点配置，按[文件说明](../.github/translation-guide.md#files-and-tools)定位。涉及论坛文案时读取[术语表](../.github/forum-glossary.md)。
3. 会话提供 x18n MCP 时，优先用其查询和检查工具；参数以工具 schema 为准。否则在仓库根目录使用 CLI：

```sh
pnpm i18n doctor --json
pnpm i18n check --json
```

`doctor` 用于确认项目如何被识别，`check` 给出修改前的诊断。记录已有问题，后续与修改后的结果比较。通过 `pnpm i18n get <key> --json` 查看词条，通过 `pnpm i18n usages <key> --json` 查调用位置，并沿动态 key 的调用方补查使用场景。

## 翻译与修改

- 根据用户指定的语言和范围处理词条，先复用已有 key。需要翻译上下文时，运行 `pnpm i18n prompt translate --to <locale>`；它输出提示词，由当前 Agent 完成翻译。
- `prompt translate` 会引用论坛术语表，处理论坛词条前读取该文件。按[翻译规则](../.github/translation-guide.md#translation-rules)保留占位符、插槽和复数分支。
- 全部语言 YAML 均可通过 x18n 写入或直接编辑，包括 `site.yml`。链接和匹配规则也会被识别，按任务范围决定是否修改；公共地址和业务 ID 留在共享配置中。
- 改名或删除 key 前检查静态引用和动态调用。静态扫描不完整时，通过源码确认，保留现有检查规则。
- 修改运行时代码时遵循[组件用法](../scripts/x18n/README.md#组件用法)，不要另建消息生成器或重复扫描器。

## 验收与交付

1. 再运行 `pnpm i18n check --json`，核对新增、消失和仍存在的诊断。调整检查规则或豁免时，说明对应词条的依据。
2. 按[提交前检查](../.github/translation-guide.md#checks-and-submission)和[接入维护检查](../scripts/x18n/README.md#查询与检查)选择验证；界面变化要检查实际页面。
3. 文件移动或改名后，结合源文与引用判断过期提示。明确记录已复核的译文，避免将历史关联变化当作翻译完成。
4. 交付时列出修改的语言与范围、实际执行的检查及结果、未解决的问题。需要验收或发布看板时，运行 `pnpm translations:build`。
